# مسار عمل استخلاص النصوص ورقمنة الكتب (OCR Workflow)

نظام متكامل لإدارة وأتمتة عمليات استخلاص النصوص العربية والإنجليزية من ملفات PDF الممسوحة ضوئياً، مع الحفاظ على التنسيق الهيكلي وضمان سلامة النصوص الدينية والأدبية وفق معايير برمجية وتدقيقية صارمة.

تمت هيكلة هذا الدليل ليكون دليلاً تشغيلياً للمستخدم البشري، يوضح كيفية إعداد البيئة وتطبيق خطوات سير العمل اليدوي، مع شرح المميزات، البنية البرمجية والسكربتات المساعدة.

---

## ١. المميزات الأساسية (Key Features)

يتميز سير العمل بالحزمة الآتية من الخصائص والأدوات المدمجة:

- **الاستخلاص المحلي المحمي (Local-First Transcription)**: تتم قراءة ملفات الـ PDF بالكامل محلياً وعبر إمكانيات النموذج الذاتية الحصرية (عبر أداة القراءة المدمجة) دون الحاجة للاتصال بمكتبات استخلاص نصوص أو محركات OCR خارجية، مما يضمن سرية البيانات وخصوصيتها.
- **التفريع التلقائي الذكي (Fast Track & Chunked Pipeline)**:
  - **المسار السريع**: ينشط للمستندات الصغيرة (20 صفحة أو أقل) لمعالجتها مباشرة دفعة واحدة دون تقسيم.
  - **المسار القياسي المجزأ**: ينشط للمستندات الكبيرة، حيث تُفتت آلياً لأجزاء (Chunks) بحد أقصى 20 صفحة للـ chunk للتشغيل الموازي السريع.
- **دعم نطاقات الصفحات المخصصة (Custom Page Ranges)**: إمكانية اختيار صفحات معينة للمعالجة (سواء نطاقات متصلة مثل `5-15` أو متفرقة مثل `5,8,10-12` أو نطاق مفتوح) عبر معامل `--pages` لتفادي معالجة الملفات الكبيرة بالكامل بلا طائل.
- **التجميع والتقسيم المتصل (Intelligent Chunking for Ranges)**: تفكيك نطاقات الصفحات غير المتصلة برمجياً إلى مجموعات متصلة وحفظها في أجزاء PDF خامة مؤقتة، مما يحافظ على الترقيم الأصلي للصفحات دون تدمير قواعد التحقق والدمج.
- **الاعتماد الحصري والكامل على Pandoc**: تحويل ملفات Markdown النهائية إلى مستندات Word (.docx) بدقة هيكلية ممتازة، تدعم الأنماط الأصلية للعناوين (Headings)، الجداول، والقوائم المتداخلة.
- **المحاذاة العربية التلقائية (Arabic RTL Layout Detection)**: استكشاف النصوص العربية تلقائياً في الملفات المخرجة وحقن محدد الاتجاه من اليمين إلى اليسار (`-M dir=rtl`) لتهيئة اتجاه الفقرات والجداول بشكل قياسي.
- **التحقق الهيكلي المستقل (Deferred Structural Validation)**: التحقق البرمجي التلقائي من واصمات الصفحات المكتوبة من قبل الوكلاء الفرعيين لضمان مطابقتها المادية للملف الأصلي قبل الدمج.
- **إلغاء فحص التكرار عند التخصيص (Conditional Duplication Check)**: فحص التكرار التلقائي للمستندات الكاملة، مع تخطيه صامتاً في حال الصفحات المخصصة لتجنب تعطل العمل بسبب الفجوات النصية العمدية.
- **التثبيت الآلي الذاتي والتعافي (Self-Healing Dependency Installer)**: كشف تلقائي عن وجود أداة `pandoc` في النظام، ومحاولة تثبيتها صامتاً عبر `winget` عند فقدانها، مع تفعيل الانهيار الصريح لإرشاد المستخدم لكيفية التثبيت اليدوي.
- **مجلدات المخرجات المنظمة (Clean Workspace Organization)**: عزل ملفات Markdown النهائية في مجلق `md/` وملفات Word في مجلد `word/` تلقائياً للحفاظ على نظافة وترتيب جذر المشروع.
- **دعم الأمانة العلمية والنسخ الشرعي والأدبي**: توجيه المخرجات للالتزام بصيغة الرسم العثماني للآيات `﴿ ﴾` والتنسيق النجمي للشعر `*` وتخريج التلف المادي والصفحات الفارغة مادياً بترميز موحد لتسهيل المراجعة.

## ٤. دليل تشغيل واستخدام مسار العمل (Execution & Operation Guide)

### أ. المتطلبات الأساسية (Prerequisites)
- تثبيت بيئة بايثون (Python 3.x) مع مكتبة `pypdf` لإدارة وتقسيم الملفات.
- أداة `pandoc` مثبتة ومسجلة في PATH، وفي حال فقدانها سيقوم السكربت بمحاولة تثبيتها صامتاً عبر `winget` تلقائياً.

### ب. خطوات العمل التفصيلية (Step-by-Step)

#### الخطوة الأولى: التمهيد وتحديد الصفحات
ضع ملف الـ PDF المراد تفريغه في مجلد `pdf/` (على سبيل المثال: `pdf/input.pdf`).
شغل سكربت التقسيم لتحديد المسار وحالة العمل:
```bash
# خيار 1: تهيئة وتقسيم كامل مستند الـ PDF
python .agents/skills/ocr-transcription/scripts/splitt_pdf.py "pdf/input.pdf"

# خيار 2: تهيئة وتقسيم صفحات مخصصة فقط (متصلة أو متفرقة)
python .agents/skills/ocr-transcription/scripts/splitt_pdf.py "pdf/input.pdf" --pages "5,8,10-12"
```

*ملاحظة تقنية*: عند تشغيل خيار الصفحات المخصصة، يقوم السكربت تلقائياً بتجميع الصفحات المحددة في مجموعات متصلة وتجزئتها لـ chunks خامة مع إلحاق اسم المخرجات النهائية باللاحقة المخصصة (مثل `input_p5_8_10-12.md`) وتثبيت حقل `is_page_selection: true` في `progress.json`.

#### الخطوة الثانية: تشغيل التحقق والدمج النهائي
بمجرد انتهاء استخلاص النصوص وكتابتها في ملفات الأجزاء المؤقتة بـ `output_parts/`؛ يتم تشغيل التحقق ثم الدمج كالتالي:
```bash
# 1. تشغيل فحص التحقق الهيكلي لكافة الأجزاء
python .agents/skills/ocr-transcription/scripts/validate_chunk.py --all

# 2. تشغيل دمج الأجزاء المعتمدة وتطهير الملفات المؤقتة
python .agents/skills/ocr-transcription/scripts/merge_parts.py
```

*ملاحظة تقنية*: يقوم سكربت الدمج بكتابة الملف النهائي داخل مجلد `md/` افتراضياً. وإذا تبيّن أن حقل `is_page_selection` مفعل، يتخطى السكربت فحص التكرار (Duplication Check) صامتاً لتلافي الأخطاء الناتجة عن الفجوات النصية العمدية.

#### الخطوة الثالثة: التحويل إلى مستند Word
لتحويل مخرجات Markdown المعتمدة إلى مستند Word ذي محاذاة وتنسيق احترافي:
```bash
python .agents/skills/ocr-transcription/scripts/convert_to_docx.py "md/input.md" "word/output.docx"
```
*ملاحظة تقنية*: يقوم السكربت بإنشاء مجلد `word/` تلقائياً إن لم يكن متواجداً. وفي حال اكتشاف نصوص عربية داخل الملف، يتم حقن المعامل `-M dir=rtl` تلقائياً لضبط اتجاه الخطوط والجداول من اليمين إلى اليسار.

## ٥. البنية البرمجية وطرق المساهمة (Contributor Guide)

للراغبين في تعديل وتطوير السكربتات المساعدة؛ يرجى مراعاة الهيكلة الوظيفية الآتية:

*   **splitt_pdf.py**:
    *   يحتوي على دالة `parse_pages()` المسؤولة عن معالجة النطاقات واستخراج أرقام الصفحات الحقيقية (1-indexed).
    *   يحتوي على دالة `group_contiguous()` المسؤولة عن تجميع الصفحات في مجموعات متصلة لتجنب تحوير السكربتات الأخرى.
*   **convert_to_docx.py**:
    *   يعتمد حصرياً على أداة `pandoc` كخيار وحيد لضمان الدقة في الجداول والعناوين.
    *   يحتوي على منطق كشف وجود الأداة في PATH والمسارات الافتراضية للويندوز، مع تشغيل التثبيت التلقائي:
        `winget install -e --id JohnMacFarlane.Pandoc --silent --accept-source-agreements --accept-package-agreements`
    *   في حال الفشل، ينهار السكربت صراحة بكود خطأ غير صفري لتمكين المستخدم من معرفة التبعية المطلوبة يدوياً.
*   **merge_parts.py**:
    *   يفحص حقل `is_page_selection` قبل استدعاء `extract_page_samples()`.
    *   يقوم بمسح كامل ملفات PDF المؤقتة للأجزاء وملف `progress.json` عند النجاح.

## ٦. ميثاق النسخ والتدقيق (Transcription Manifesto Summary)

تلتزم جميع عمليات الاستخلاص بملف القواعد الموحد **[transcription_rules.md](.agents/skills/ocr-transcription/references/transcription_rules.md)**، والذي ينص على:
*   **الأمانة المطلقة**: عدم تحوير المتن الأصلي للمستند وتخريج الأخطاء المطبعية في هوامش سفلية.
*   **الترقيم الفاصل**: تثبيت واصم الصفحات قياسياً: `--- Page [Number] ---`.
*   **الشرعيات والأدب**: إثبات الآيات بالرسم العثماني المحكم بين أقواس `﴿ ﴾` وفصل الشطرين الشعريين بـ `*`.
*   **مناقلة الملفات**: حظر إعادة توليد الملفات الطويلة وتوليدها كلياً لمجرد النسخ أو النقل؛ واستخدام أوامر نظام التشغيل المباشرة مثل `Move-Item` أو `Copy-Item` لترشيد الاستهلاك.
