# مسار عمل استخلاص النصوص ورقمنة الكتب (OCR Workflow)

نظام متكامل لإدارة وأتمتة عمليات استخلاص النصوص العربية والإنجليزية من ملفات PDF الممسوحة ضوئياً، مع الحفاظ على التنسيق الهيكلي وضمان سلامة النصوص الدينية والأدبية وفق معايير برمجية وتدقيقية صارمة.

## ٢. الهيكل التنظيمي للمستودع (Repository Structure)

يتكون المشروع من المجلدات والملفات الرئيسية التالية:

- **[skill.md](skill.md)**: المرجعية المعمارية الكلية التي تضبط مسار العمل للوكلاء (المستند التوجيهي الرئيسي).
- **[scripts/](scripts/)**: المجلد المحتوي على السكربتات المساعدة لإدارة وتسيير مراحل العمل:
  - **[init_workflow.py](scripts/init_workflow.py)**: نقطة الانطلاق لتهيئة مسار العمل لملف PDF محدد.
  - **[splitt_pdf.py](scripts/splitt_pdf.py)**: تقسيم ملفات PDF الكبيرة إلى أجزاء ثابتة الحجم (20 صفحة للجزء) وتوليد سجل المتابعة.
  - **[validate_chunk.py](scripts/validate_chunk.py)**: فحص الأجزاء المستخلصة والتأكد من مطابقتها الهيكلية للمعايير المعتمدة.
  - **[merge_parts.py](scripts/merge_parts.py)**: دمج الأجزاء المعتمدة وتدقيقها ضد التكرار قبل إخراج الملف النهائي.
  - **[convert_to_docx.py](scripts/convert_to_docx.py)**: تحويل مخرجات Markdown النهائية إلى مستندات Word (.docx) منسقة.
- **[references/](references/)**: مجلد الوثائق المرجعية:
  - **[transcription_rules.md](references/transcription_rules.md)**: ميثاق النسخ والتدقيق التفصيلي وقواعد التعامل مع النصوص والصور والتلف المادي.
- **[pdf/](pdf/)**: المجلد المخصص لاستقبال ملفات PDF المصدر (توضع فيه الكتب المراد تفريغها).
- **[output_parts/](output_parts/)**: المجلد المؤقت الذي تودع فيه الأجزاء المقسمة والمستخلصة وسجل التقدم (`progress.json`).
- **[md/](md/)**: المجلد المخصص لاستلام ملفات Markdown (.md) النهائية الناتجة عن الدمج.
- **[word/](word/)**: المجلد المخصص لاستلام ملفات Word (.docx) النهائية الناتجة عن التحويل التلقائي.

---

> [!IMPORTANT]
> **إرشادات تهيئة هيكل المجلدات**:
> يحتوي الملف المضغوط المرفق بالإصدار (`ocr-workflow.zip`) على المجلدات الثلاثة (`pdf/`, `md/`, `word/`) كبنية فارغة مهيأة للعمل الفوري:
> 1. **مجلد `pdf/`**: يجب وضع ملف PDF المراد معالجته فيه قبل تشغيل سكربت التهيئة.
> 2. **مجلد `md/`**: ستنتج فيه تلقائياً النسخة النصية الكاملة للكتاب بصيغة Markdown بعد الدمج.
> 3. **مجلد `word/`**: ستنتج فيه تلقائياً النسخة النهائية المنسقة بصيغة Word (.docx) بعد انتهاء الدمج والتدقيق مباشرة.


## ٣. دورة حياة التنفيذ وسير العمل (Sequential Execution Pipeline)

يسير العمل برمجياً وتنسيقياً وفق الخطوات التتابعية التالية:

### الخطوة الأولى: التهيئة والتقسيم الهيكلي
- **بروتوكول تعدد الملفات (Multi-file Protocol)**: إذا وجد الوكيل الرئيسي أكثر من ملف PDF في مجلد المصدر، ينبه المستخدم لتخييره بين معالجة ملف واحد محدد أو معالجة كافة الملفات بالتتابع (واحداً تلو الآخر).
- يتم تهيئة ملف PDF النشط بتشغيل:
```bash
python scripts/init_workflow.py "pdf/input.pdf"
```
- **حجم الجزء الحاسم (Hard Limit)**: الحد المعماري للتقسيم هو 20 صفحة كحد أقصى للجزء ولا يُعدّل بأي معامل اختياري.
- إذا كان الملف يحتوي 20 صفحة أو أقل، يُهيّأ سجل المتابعة `progress.json` دون تقسيم فعلي. وإذا زاد على ذلك، يتم تقسيمه لأجزاء مستقلة في مجلد `output_parts`.

### الخطوة الثانية: الاستخلاص الموازي وصلاحيات الوكلاء
- يتولى الوكيل الرئيسي إسناد المهام للأجزاء ذات الحالة `pending` إلى الوكلاء الفرعيين بالتوازي في مجموعات (Batches) لا تتعدى 10 وكلاء في آن واحد لتفادي نفاد الحصص البرمجية (API Quotas).
- **صلاحيات الوكلاء الفرعيين**: ينحصر عمل الوكلاء الفرعيين في استخلاص النص وحفظه في الملف المؤقت `output_parts/part_N_temp.md` رعايةً للتعليمات في `references/transcription_rules.md`. ويُمنعون منعاً باتاً من تشغيل التحقق البرمجي أو تعديل سجل المتابعة.
- **الاعتماد الحصري للنسخ**: يُحظر استخدام أي مكتبات استخلاص نصوص أو OCR خارجية (مثل pdfplumber أو PyMuPDF أو tesseract). ويجب حصرياً الاعتماد على أداة `view_file` المدمجة لقراءة صفحات الـ PDF بالقدرات الذاتية للنموذج.
- تُحفظ المخرجات الأولية لكل جزء بصيغة مؤقتة: `output_parts/part_N_temp.md`.

### الخطوة الثالثة: التحقق المؤجل (Deferred Validation)
بعد استكمال استخلاص كافة الأجزاء وولادة جميع الملفات النصية المؤقتة، يتم استدعاء سكربت التحقق:
```bash
python scripts/validate_chunk.py --all
```
يقوم السكربت بفحص المخرجات والتأكد من مطابقة الصفحات المستخلصة وواصماتها للحدود المعينة في سجل المتابعة. في حال النجاح، يُنشأ ملف المخرجات المعتمد وتتحول الحالة في `progress.json` إلى `completed`؛ وفي حال الفشل تتحول إلى `failed`.

### الخطوة الرابعة: التعافي من الأخطاء
- عند فشل جزء ما، يقوم الوكيل الرئيسي بحذف ملف المخرجات المؤقت الفاشل وإعادة إطلاق وكيل فرعي لمعالجة هذا الجزء تحديداً لتلافي الخلل، ثم إعادة فحصه.
- في حال حدوث خطأ بيئي أو برمجي في تشغيل السكربتات المساعدة، يتم تجميد المهمة فوراً (Script Failure Freeze Protocol) وتنبيه المستخدم.

### الخطوة الخامسة: الدمج والتدقيق النهائي
عند اكتمال كافة الأجزاء بنجاح ووسمها بـ `completed` في سجل المتابعة، يتم دمج الأجزاء بتشغيل:
```bash
python scripts/merge_parts.py
```
- يقوم السكربت تلقائياً باستدعاء منطق فحص التكرار الداخلي عبر أخذ عينات من الصفحات وفحص مطابقتها.
- إذا تم كشف تكرار للمحتوى، تُجمد العملية وتُحفظ الملفات الوسيطة للمراجعة وتوليد تقرير في `sampling_preview.txt` مع إرجاع كود خطأ.
- في حال اجتياز الفحص بنجاح، تُدمج الأجزاء في ملف مخرجات نهائي باسم الكتاب الأصلي بصيغة Markdown ويُحفظ داخل مجلد `md/`، مع تنظيف وحذف كافة الأجزاء الوسيطة وسجلات التقدم تلقائياً.

### الخطوة السادسة: التحويل التلقائي إلى تنسيق Word
يقوم الوكيل الرئيسي تلقائياً بتشغيل سكربت التحويل فور انتهاء عملية الدمج والتدقيق بنجاح لتحويل ملف Markdown النهائي إلى مستند Word منسق وحفظه في مجلد `word/`:
```bash
python scripts/convert_to_docx.py "md/output_file.md" "word/output_file.docx"
```

## ٤. ميثاق النسخ والتدقيق (Transcription Manifesto)

يلتزم كافة الوكلاء الفرعيين بضوابط صارمة ومفصلة في ملف **[transcription_rules.md](references/transcription_rules.md)**، وأبرز ملامحها:

- **الأمانة العلمية**: يُمنع إضافة أي حواصر أو علامات خارجية على المتن الأصلي. ويتم تصحيح الأخطاء المطبعية الواضحة وإدراج اللفظ المصحح في المتن متبوعاً بحاشية تشير إلى اللفظ الأصلي المحرف في تذييل الصفحة بالصيغة: `[^N]: في الأصل: "اللفظ_المحرف"`.
- **فواصل الصفحات**: تبدأ كل صفحة بواصلة الهوية في أول سطر بالصيغة: `--- Page [Number] ---`.
- **الحواشي والمهمشات**: تُجمع النصوص الجانبية تحت عنوان `### Marginalia` وتُدرج الحواشي السفلية تحت فاصل `--- Footnotes ---` في تذييل الصفحة.
- **النصوص الدينية والأدبية**: تُكتب الآيات بالرسم العثماني وتُحصر بين أقواس مزخرفة `﴿ ﴾`؛ ويُفصل بين شطري البيت الشعري بمسافة ونجمة واحدة: `الصدر * العجز`.
- **التلف المادي والصفحات المفقودة**: تُثبت واصمات الصفحات التالفة أو المفقودة أو الفارغة في موضعها مع إلحاقها بالوسم الموحد الموضح لسبب التلف أو الفقد أو الخلو (مثل: `[صفحة فارغة فعلياً: صفحة بيضاء فاصلة بين الفصول]`) لضمان عدم تعطل الفحص البرمجي التلقائي وسير العمل.
