# قواعد بروتوكول تحويل صفحات PDF إلى صور (PDF Image Pipeline Rules)

يُستعمل هذا المسار حين يطلب المستخدم صوراً مستقلة للصفحات قبل إدخالها إلى سير المعالجة أو إرسالها لنموذج الرؤية. 

## ١. تعليمات الاستدعاء وأوامر التشغيل

```powershell
python .agents/skills/ocr-transcription/scripts/pdf_to_images.py "pdf/input.pdf" --output-dir "output_images"

# صفحات محددة
python .agents/skills/ocr-transcription/scripts/pdf_to_images.py "pdf/input.pdf" --pages "1-3,8"

# معرفة العدد دون إنشاء صور
python .agents/skills/ocr-transcription/scripts/pdf_to_images.py "pdf/input.pdf" --info-only
```

## ٢. ضوابط المعالجة وحفظ الحالة

- **تسمية المخرجات**: يخرج السكربت PNG مستقلاً لكل صفحة، مع ترقيم أصلي ثابت مثل `book_p001.png`.
- **أداة الرسم**: يستعمل السكربت مكتبة `PyMuPDF` (المسماة `fitz`) للرسم البصري الحقيقي للصفحة، وهي أسرع وأدق في تنعيم الحروف العربية من مكتبات الرسم الأخرى.
- **حالة الاستئناف**: تُحفظ حالة الاستئناف في الملف المؤقت `output_images/.progress.json` ويُحدّث ذرياً عقب إتمام كل صفحة بنجاح.
- **حماية المجلد**: لا يعيد السكربت تشغيل المعالجة في مجلد مخرجات غير فارغ ما لم يجد فيه ملف الحالة الخاص بالاستئناف، تفادياً لطمس ملفات سابقة أو تداخل مخرجات مختلفة.
- **سير المعالجة اللاحقة**: لا تُرسل الصور الناتجة إلى نموذج الذكاء الاصطناعي أو تُستخلص نصوصها آلياً بمجرد تشغيل هذا المسار؛ فهو مخصص لتهيئة الصور فحسب، ومن ثم يتولى الوكيل معالجة الصور وقراءتها وفق القواعد العامة للمهارة.

## ٣. سلوك معالجة الأخطاء والنطاقات المرن (Clamping)

يتبع السكربت سلوكاً متسامحاً مع مدخلات أرقام الصفحات الفاسدة أو الخارجة عن الحدود ليتطابق مع بقية أجزاء المشروع:
- **اقتطاع النطاقات (Clamping)**: عند إدخال نطاق يتجاوز أبعاد المستند (مثال: `1-200` لمستند من `177` صفحة)، يقتطع السكربت النطاق تلقائياً إلى الحدود القصوى المتاحة للمستند (`1-177`) مع طباعة تحذير على `sys.stderr`.
- **تجاوز الرموز الفاسدة**: يتم تجاهل الرموز غير الرقمية أو النطاقات الفاسدة بصمت مع طباعة تحذير ملائم وتكملة معالجة بقية النطاقات الصالحة دون توقف السكربت أو تحطمه.
