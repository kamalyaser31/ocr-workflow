# بروتوكول إدارة التشغيل والتعافي من الأخطاء (Execution & Recovery Protocol)

يُعنى هذا الملف بضبط سلوك الوكيل الرئيسي عند مواجهة أخطاء أثناء تشغيل السكربتات المساعدة أو فشل الـ **chunks** في التحقق المالي.

---

## أولاً: بروتوكول تجميد العمل عند فشل السكربتات (Script Failure Freeze Protocol)

إذا فشل تشغيل أي سكربت مساعد (مثل `splitt_pdf.py` أو `validate_chunk.py` أو `merge_parts.py` أو `convert_to_docx.py`) لسبب بيئي أو تقني بحت (نحو: استثناء برمجى Python Exception، خطأ في الصلاحيات Permission Error، نفاد الذاكرة، أو عدم توفر مكتبة معينة)، **يجب على الوكيل الرئيسي تجميد العمل فوراً والتوقف عن اتخاذ أي خطوة أخرى**.
- يُمنع محاولة تخطي الخطأ برمجياً أو تجاهله.
- يجب إبلاغ المستخدم فوراً بتقرير صريح يضم:
  1. اسم السكربت المتعطل ومساره.
  2. نص الخطأ البرمجي كاملاً (Traceback).
  3. رقم الـ **chunk** المتأثر بالخلل.
  4. انتظار توجيهات المستخدم وتدخله اليدوي لحل المشكلة البيئية.

---

## ثانياً: بروتوكول التعافي من فشل التحقق للـ chunks

إذا وسم سكربت التحقق أحد الـ **chunks** بالحالة `"failed"` في ملف المتابعة `progress.json`:
1. **منع التجاوز التقديري**: يُحظر تماماً التجاوز التقديري للخطأ أو افتراض خلو الصفحات دون التحقق الحسي اليقيني منها.
2. **حذف الملف التالف**: يقوم الوكيل الرئيسي بحذف ملف المخرجات المؤقت الفاشل للجزئية (`output_parts/part_N_temp.md`) من القرص فوراً.
3. **إعادة الاستخلاص**: يُعيد الوكيل الرئيسي إطلاق وكيل فرعي لاستخلاص الـ **chunk** بالكامل من البداية وكتابته في `output_parts/part_N_temp.md` مع توجيهه لتفادي مواضع السقط السابقة.
4. **إعادة التحقق الفردي**: بعد انتهاء استخلاص الـ **chunk** المعاد، يُشغل الوكيل الرئيسي سكربت التحقق للـ **chunk** المحدد بمفرده:
   ```bash
   python scripts/validate_chunk.py [N]
   ```
   *(حيث [N] هو رقم الـ chunk المعني).*
5. لا ينتقل العمل للخطوات التالية حتى تتحول حالة الـ **chunk** في ملف المتابعة إلى `"completed"`.
